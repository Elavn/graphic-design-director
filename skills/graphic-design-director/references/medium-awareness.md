# Medium awareness: artwork is not automatically a website

## Detect the output surface

- **Standalone illustration / text-free ad:** no page furniture, nav, logos, labels, words or watermark unless specified. Preserve explicit copy-safe empty regions.
- **Print poster / outdoor ad:** idea, image, headline and required factual info only; no invented metadata, footer credits, profile bars or bookmarking controls.
- **Social feed graphic:** the graphic itself, not a screenshot of the app around it. Platform safe zones matter, but do **not** draw the platform UI.
- **Editorial cover:** masthead/headlines only when the brief asks for a cover; don't convert every poster into a magazine cover.
- **Brand system / packaging:** real identity, logo clear-space and required production content; no mock-browser chrome unless requested.
- **Slide presentation:** audience-facing slide content; not fake slide-editor toolbars.
- **Website/app design:** navigation, buttons, cards, form controls, cursor states and UI chrome are valid when functionally relevant.
- **Exact screenshot replication:** replicate UI as part of the source when explicitly requested; distinguish it from a user asking to extract and recreate the artwork depicted inside the screenshot.

## UI contamination checklist

Before approval, look for: navigation words, bookmark icons, search icons, tiny creator credits, menu bars, floating fake buttons, app windows, cursor arrows, pill labels, fake badges, watermarks and dotted browser grids. If any appear without a legitimate brief reason, remove them. Note: an explicitly requested **blank pill-shaped price tag** is a legitimate graphic object and must not be removed or mutated into a speech bubble.

## Strong art direction without interface garnish

Use framing, negative space, shape language, scale, color contrast, accurate materials, expressive typography (if requested) and visual story to produce sophistication; do not rely on small UI tokens to make a graphic feel "designed".
